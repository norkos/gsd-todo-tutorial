## Phase Goal

**As a** command-line user, **I want to** add to-do items and list them with `node todo.js add "<text>"` / `node todo.js list`, **so that** my items are saved in `./todos.json` and are still there the next time I run the tool.

> Note: ROADMAP.md's Phase 1 `**Goal:**` line is outcome-phrased rather than user-story phrased; the story above is a direct restatement of it (same role, capability, outcome) — no scope added.

Purpose: Proves the full stack end to end — command line ("UI") → command dispatch → storage module → `todos.json` ("DB") — and fixes the architectural decisions (layout, storage format, test style) that Phases 2 and 3 build on. See `01-SKELETON.md`.
Output: `package.json`, `todo.js`, `lib/store.js`, `test/todo.test.js`.
</objective>

lib/store.js (CommonJS, module.exports = { todosPath, loadTodos, saveTodos }):
- todosPath(): string — returns path.join(process.cwd(), 'todos.json'), resolved at call time (not at module load).
- loadTodos(): { version: 1, items: Array<{ text: string, done: boolean }> }
    - If todos.json does not exist (fs error code 'ENOENT'): returns { version: 1, items: [] } and does NOT create the file.
    - Otherwise: JSON.parse(fs.readFileSync(todosPath(), 'utf8')) and returns it. Other errors are re-thrown (Phase 2 owns corrupt-file reporting).
- saveTodos(data): void
    - Serialises with JSON.stringify(data, null, 2) + '\n'.
    - Writes to temp path path.join(path.dirname(todosPath()), '.todos.json.' + process.pid + '.tmp'), then fs.renameSync(tmp, todosPath()).
    - On any error: best-effort fs.unlinkSync(tmp) inside its own try/catch, then re-throw the original error.

todo.js (CLI entry, CommonJS):
- argv = process.argv.slice(2); command = argv[0].
- 'add': text = argv.slice(1).join(' ').trim(); push { text, done: false }; saveTodos; stdout `Added ${n}. ${text}\n` where n = items.length after push.
- 'list': empty → stdout `No items yet. Add one with: todo add "<text>"\n`; else one line per item `${i + 1}. [${done ? 'x' : ' '}] ${text}\n`, written as a single process.stdout.write call.
- anything else: process.exitCode = 1 with no output (usage text and messages are ERR-03, Phase 2).

<threat_model>
## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| argv → process | Untrusted item text from the command line |
| todos.json → process | File in cwd may be edited by the user/other tools; parsed with JSON.parse |
| process → todos.json | Writes user data; a partial write would lose items (core value) |

## STRIDE Threat Register

| Threat ID | Category | Component | Disposition | Mitigation Plan |
|-----------|----------|-----------|-------------|-----------------|
| T-01-01 | Tampering (integrity/data loss) | lib/store.js saveTodos | mitigate | D-04 atomic save: writeFileSync to `.todos.json.<pid>.tmp` in same dir, then renameSync over todos.json; tmp unlinked on failure; test asserts no leftover temp file |
| T-01-02 | Tampering (path) | lib/store.js todosPath | mitigate | Path is fixed `path.join(process.cwd(), 'todos.json')`; no user input contributes to any file path, so argv cannot redirect writes |
| T-01-03 | Tampering (injection) | todo.js add | accept | Item text is stored via JSON.stringify and printed verbatim to the user's own terminal; no shell, eval, or template execution. Terminal escape sequences in user's own items are self-inflicted |
| T-01-04 | Tampering (prototype pollution) | lib/store.js loadTodos | accept | JSON.parse result is only read (items array iterated); never merged into other objects via Object.assign/spread of untrusted keys |
| T-01-05 | Denial of Service | lib/store.js loadTodos | accept | Malformed todos.json throws (process exits non-zero, file untouched since list doesn't write and add throws before save). Clear reporting is STOR-03 in Phase 2 |
| T-01-06 | Information Disclosure | todos.json | accept | Local per-user file with default umask; no secrets; single-user CLI |
| T-01-07 | Tampering (test isolation) | test/todo.test.js | mitigate | Every test uses fs.mkdtempSync cwd and rmSync cleanup; never runs against repo cwd |
</threat_model>
